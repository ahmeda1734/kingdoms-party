# KINGDOMS PARTY — Game Design Document (v0.1)

لعبة استراتيجية 2D أونلاينة Real-Time على المتصفح، مستوحاة من العمق الاقتصادي في Age of Empires وسهولة اللعب الجماعي في Mini Kingdoms، بهوية كرتونية مبهجة.

الفريق الافتراضي: Game Director / Game Designer / Multiplayer Network Engineer / Frontend Dev / Backend Dev / UI-UX / Balance Designer.

---

## 1. دورة اللعب الكاملة (Core Loop)

**دقيقة بدقيقة:** تكلف العمال بموارد → تبني مبانٍ جديدة → تفتح تقنيات وترقيات → تنتقل لعصر أعلى → تنافس على النقاط الاستراتيجية والموارد المحايدة → تكمل أحد أشكال الفوز.

- **حلقة قصيرة (30 ثانية):** كلّف عمالاً / ابنِ / راقب الإنتاج.
- **حلقة متوسطة (5 دقائق):** قرار عصر جديد، توسع اقتصادي، أول علاقة تحالف.
- **حلقة طويلة (20–60 دقيقة):** معركة موارد، نقاط سيطرة، حسم نمط الفوز، احتفال النهاية مع إحصاءات.

**مثال مباراة نموذجية (غرفة أصدقاء 4):**
1. الدقائق 0–3: التعرف على منطقتك، توزيع العمال (خشب ثم طعام).
2. 3–8: بيوت سكان، مزرعة، منشرة → التوسع من 5 عمال إلى 15.
3. 8–15: العصر الثاني — بداية الحماية (أبراج/أسوار لاحقاً)، ومنافسة على منجم الذهب المحايد بوسط الخريطة.
4. 15–35: إما اقتصاد نحو «السيطرة الاقتصادية»، أو ضغط وحدات على أضعف مملكة، أو تحالف 2v2.
5. النهاية: شاشة احتفالية بالترتيب والإحصاءات (الموارد المجموعة، البنايات، أفضل اقتصاد/استكشاف/تعاون).

## 2. نظام الموارد والتكاليف (مسودة توازن v1)

| المورد | المصدر | الاستخدام | ملاحظات |
|---|---|---|---|
| الخشب 🪵 | أشجار | أكثر المباني | المورد الأول لكل بداية |
| الحجر 🪨 | محاجر/صخور | دفاعيات ومباني متقدمة | جمعه أبطأ لكنه ذخيرة |
| الذهب 💰 | مناجم | تدريب، تقنيات، تجارة | نقطة التنافس الجغرافية |
| الطعام 🍎 | مزارع وجني | نمو السكان والوحدات | مورد التدفق الدائم |
| الطابوق 🧱 | معمل طابوق (طين + خشب) | المباني الفخمة والمتطورة | مورد «قيمة مضافة» |

**معادلات الجمع الأساسية (نقطة البداية للمعايرة):**
- العامل يحمل 10 وحدات؛ معدل الجمع/ثانية: خشب 3.3 / طعام 3.0 / حجر 2.4 / ذهب 2.2.
- تكلفة عامل جديد: 50 طعام (+30 ذهب من العصر الثالث).
- العامل يعمل تلقائياً ويعود للمخزن ثم يكمل نفس نوع المورد دون تدخل — نوفّر الإدارة الصغيرة ونحفظ قرارات التوزيع الكبرى.

**أمثلة تكاليف (تُعاد معايرتها كل مرحلة):**
- بيت سكان: 60 خشب → +4 سكان.
- مزرعة: 45 خشب → إنتاج طعام مستمر (1–2 عامل).
- منشرة: 100 خشب + 40 حجر → +25% كفاءة الخشب للعامل ضمن نطاق.
- معمل طابوق: 120 خشب + 80 حجر → 2 طعام + 1 حجر ⇐ 2 طابوق/دقيقة لكل عامل مكلَّف.
- السوق: أسعار مرجعية + تداول حلفاء بسعر مفضل.

## 3. قائمة المباني ووظائفها

| المجموعة | المبنى | الوظيفة |
|---|---|---|
| اقتصادية | القلعة الرئيسية | نقطة الإيداع وتدريب العمال؛ دمارها = خسارة المملكة |
| | بيوت السكان | رفع سقف العمال |
| | المخزن | نقطة إيداع إضافية تختصر مسير العمال |
| | المزرعة | إنتاج طعام |
| | منشرة / محجر / منجم / معمل طابوق | مضاعفات وجمع متخصص |
| | السوق | تداول وأسعار |
| | الطاحونة | تحسين مخرجات المزارع |
| تطويرية | الأكاديمية / المكتبة / مركز الأبحاث | أبحاث الاقتصاد والجمع والوحدات |
| | ورشة الحرفيين | بناء وإصلاح أسرع |
| | مركز التجارة | قوافل مع الحلفاء من العصر 3 |
| خاصة | برج المراقبة / أسوار / بوابة | دفاع ورؤية (قتال كرتوني مبسط) |
| | ساحة / نافورة / حديقة / تمثال | «البهاء» — يغذي أنماط الفوز الاقتصادية ومكافآت صغيرة |

كل مبنى: تكلفة ووقت ومساحة بلاطات ومستويات 1–3 بشكل بصري مختلف + بناء تدريجي (هيكل → نهائي).

## 4. الوحدات والأدوار

| الوحدة | الدور | نقاط قوة | نقطة ضعف |
|---|---|---|---|
| الحارس | قتال متوازن | رخيص ومرن | لا يتفوق في أي مسرح |
| الحامي | خط متقدم ودرع | صحة عالية | بطيء وضرره منخفض |
| المستكشف | استكشاف | أسرع ورؤية واسعة | ضعيف قتالياً |
| الرامي | دعم بعيد | يعاتي من بعيد | هشّ عند الاقتراب |
| الفارس | مناورة | تنفيذ سريع على الرماة والمستكشفين | غالٍ ويُفشل أمام الحامي |
| المهندس | لوجستي | بناء وإصلاح تحت الضغط | عاجز قتالياً |
| المعالج | دعم | تدعيم وحدات قريبة | لا يقاتل |
| وحدات دعم خاصة | مؤقت محدود (سرعة/وهم/دفعة اقتصاد) | أوراق قرار | وقت انتظار ونطاق ضيق |

**قواعد التوازن الإلزامية:** لا وحدة خارقة، لا وحدة عديمة الفائدة، لا «الأغلى = الأفضل»، سقف للتطويرات التراكمية (للاعب المتأخر فرصة)، لكل دور قيمة في تشكيلات مختلفة، اختبار المواجهات المتكافئة اقتصادياً، والفوز ممكن للاعب المتأخر عبر تخطيط أفضل.

## 5. نظام العصور

| العصر | متطلبات الانتقال | ما يفتحه |
|---|---|---|
| 1 — عصر القرية | — | اقتصاد أساسي، استكشاف، توسع |
| 2 — عصر المملكة | 800 طعام + 600 خشب | دفاعيات، منشرة/محجر متقدم، إدارة عمال أفضل |
| 3 — الازدهار | 1200 طعام + 1000 ذهب | تجارة متقدمة، أبحاث اقتصادية، وحدات دعم |
| 4 — الحضارة | 2000 طعام + 1500 ذهب + صروح ترف | اقتصاد واسع + خيارات فوز متقدمة |

**قاعدة حرجة ممنهجة:** الوصول للعصر 4 لا يمنح وحدات قاهرة؛ يعطي خيارات فقط — الفوز يبقى بدلالات النمط المختار (اقتصاد/نقاط/تطور) أو التفوق التكتيكي؛ لذلك يبقى ضغط التحالفات صالحاً حتى النهاية.

## 6. نظام Multiplayer (Server Authoritative)

- Node.js + WebSocket بروتوكول مباشر (`ws`) — لا محاكاة محلية ولا Multiplayer شكلي.
- **السيرفر هو حقيقة اللعبة:** tick 15Hz، أوامر العميل تُفحص ثم تُطبق فقط على السيرفر.
- كل عميل يبني العالم من `gameInit` (بذرة + terrain RLE + عقد الموارد) ويتبادل `snapshot` دلتا كل ~133ms (مواده، عماله، رؤية الآخرين، دلتا عقد وموارد وضباب) ويكمل الحركة بإنطار ما بين اللقطات.
- **ضباب الحرب سيرفري:** حساب الرؤية لكل لاعب على السيرفر، ولا يُرسل غير المرئي/المكتشف.
- حماية من الغش: لا قرار كبير على العميل.
- فقدان الاتصال: رمز جلسة في `sessionStorage`، إعادة اتصال تلقائية، بقاء الحالة على السيرفر وعودة اللاعب لنفس الخانة، والمباراة لا تتوقف عند سقوط لاعب (القوافل القتالية لاحقاً ستتحول للـ AI).

## 7. مخطط حالة المباراة وقاعدة البيانات

**حالة المباراة (الذاكرة بالسيرفر):** كائن الغرفة = مشاركون (token و slot) + Sim (terrain, nodes, units, stocks, fog, tick). الخطط للمرحلة 4:

| جدول | الحقول | الغرض |
|---|---|---|
| matches | match_id, room_code, seed, started_at, state, snapshot(BLOB) | استمرار مباراة عبر إعادة تشغيل السيرفر |
| match_players | match_id, player_key, pid, token_hash, kingdom_name, stats_json | وعي بأصحاب الخانات |
| user_profiles | player_key, nickname, achievements_json | (مرحلة لاحقة) حسابات |
| balance_results | patch_version, matchup, winner, duration | سجل قرارات الموازنة الآلي |

في المرحلة 1 لا قاعدة بيانات: الحالة بالذاكرة تصميم صحيح للمباريات القصيرة؛ SQLite تُرفع في المرحلة 4.

## 8. بنية ملفات المشروع

```
kingdoms-party/
├─ server/          # السيرفر: حقيقة اللعبة
│  ├─ app.js        # HTTP + WS + static
│  ├─ rooms.js      # غرف، جاهزية، snapshots تأنيس لكل لاعب، إعادة اتصال
│  ├─ sim.js        # قلب المحاكاة: مسارات، جمع، أوامر
│  └─ index.js      # نقطة إقلاع
├─ shared/          # لغة مشتركة للطرفين
│  ├─ constants.js / mapgen.js / noise.js / rng.js / protocol.js
├─ client/
│  ├─ index.html / css/style.css
│  └─ js/ main.js, net.js, world.js, camera.js, input.js, render.js, ui.js
├─ docs/            # هذا المستند
└─ test/            # اختبارات محاكاة + شبكة حقيقية
```

قاعدة معمارية: منطق اللعبة في `shared` + `server/sim.js` فقط؛ العرض في `client`؛ الشبكة عقد موثق في `shared/protocol.js`.

## 9. خطة اختبار التوازن

1. **ساحات جافة:** سكربت يشغّل محاكاة 2 AI بنفس البذرة واستراتيجيات قياس موحدة، ويقيس: زمن بلوغ 1000 خشب، تكلفة زمنية لوحدة، زمن عصر.
2. **مصفوفة مواجهات:** كل زوج وحدات A×B بميزانيات متساوية → النطاق الهدف 45–55%.
3. **التركيبات:** لا تركيبة تتجاوز 65% فوز ضد أي تركيبة أخرى.
4. **سقف التطويرات:** لكل سطّر تطوير، تقييد الخرج بحد أقصى، والمواجهة المتكافئة تُعاد.
5. **سجل جداول توازن:** نتائج المواجهات توثق لكل patch في `balance_results`.

## 10. خطة التنفيذ المرحلي (الحالة)

| المرحلة | المحتوى | الحالة |
|---|---|---|
| 1 — الأساس | هيكل + خريطة حتمية + كاميرا + عمال يتحركون ويجمعون + موارد + بنية multiplayer تعمل فعلاً | ✅ منفذة ومختبرَة |
| 2 — الاقتصاد والبناء | وضع البناء وقائمة المباني والمخازن وشاشة إحصائيات كاملة | ✅ منفذة ومختبرة (التطويرات والسوق قادمة في مرحلة 3) |

| 5 — اللمسات النهائية | أصوات ومؤثرات وحفظ دائم وأدوات توازن وتحسينات أداء | قادمة |

### حدود المرحلة 2 الحالية (صراحة)
- منفذ: بناء 7 مبانٍ اقتصادية فعّالة (بيت/مزرعة/مخزن/منشرة/محجر/منجم/معمل طابوق)، وقت بناء بتقدم مرئي، سعة تخزين مع فقد الفائض عند الامتلاء، تدريب عمال من القلعة، هالات +25% للجمع، تحويل حجر → طابوق عبر عمّال مكلَّفين، إيداع لأقرب مخزن.
- لا يوجد بعد: السوق والطاحونة والمباني التطويرية/الخاصة، مستويات ترقية المباني (المباني بلا مستويات حالياً)، وحدات قتالية، عصور متقدمة، AI، تداول بين اللاعبين.
- لا حفظ دائم على القرص (الحالة بالذاكرة تصميم صحيح للمباريات القصيرة).
